记录日期：2026-09-23  
用途：后续产品、前后端实现与数据/模型设计的共同需求基线  

## 一、来源文档与要求边界

本记录基于用户提供的两份说明文档整理。下文的“文档要求”代表来源文档明确提出的内容；“整理备注”是为后续执行而归纳或指出的待确认事项，不替代原始文档。

1. 前端：《期货智能分析平台_前端需求说明.docx》，V1.0，面向 UI/前端设计与开发。

## 二、项目共同基线

### 文档要求

- 建设以真实市场和产业数据为基础的沥青期货智能分析平台，第一阶段仅覆盖 BU；架构为未来增加原油、黄金、铜、螺纹钢等品种留出扩展能力。
- 平台服务于专业研究、数据统计、分析、可视化与多周期预测。强调真实、可追溯、可回测、可扩展，不承诺稳定预测市场。
- 预测必须由可验证数据与模型产生，展示历史表现、预测区间、置信信息及主要驱动因素。数据不足、异常或信号较弱时应明确提示不确定性或暂停该周期预测。
- 第一阶段优先使用免费、公开、合规的数据源；数据源不足时标明暂缺，不以无法验证的估算值冒充真实数据。
- 不做自动交易/下单，不以 LLM 取代预测模型；LLM 仅可将真实模型输出转述为自然语言解释，不得臆造价格、概率或置信区间。
- MVP原则：真实数据优先于漂亮数字；可验证模型优先于黑箱结论；简单有效优先于复杂但无增量。超出 P0 数据、预测、验证或平台可用性的需求原则上进入后续 backlog。

### 合约与预测范围

- 标的为石油沥青 BU，核心观察当前主力合约，辅助观察主力之后最近的两个合约。
- 自动识别主力、记录切换时间和依据；始终保存原始单合约数据。连续序列单独生成并记录复权/拼接方法及版本，原始价格不得修改。
- MVP支持五个预测周期：5分钟、30分钟、1天、1个月、3个月。
- 预测输出统一包含：方向、概率/置信信息、预测价格、预测区间。概率须经校准或其他可验证统计方法产生。

## 三、前端界面需求（来源：前端需求说明）

### 1. 基本面页面

- 展示期货品种/主力合约、交易所、最新价格及涨跌幅、现货价格、基差（现货减期货）；可提示主力识别/换月。
- 删除“供给压力”“需求强度”旧模块，以库存为核心可视化区域。
- 展示总库存、最新数值、周度/环比变化，并必须配图；建议周度时间序列折线图及华东、华北、华南等区域库存概览。
- 展示最近相关资讯，主题覆盖库存、产业、供需、宏观政策、上下游和市场动态。每条建议有时间、类别、标题、摘要和“查看更多”入口。

### 2. 数据可视化页面

导航结构为“实时行情 / 库存 / 多个合约对比”；各区域可包含多张图表。

- 实时行情：盘中分时、日线（可扩展为 K 线/OHLC）、高频/最新价格、成交量、MA/MACD/RSI 等技术指标；支持实时、1分钟、5分钟、日线等周期切换。
- 库存：总库存时间序列、区域对比、同比/环比、跨年季节性；后续可增加仓单、社会库存、厂库库存等口径。
- 合约对比：主力及其他期限合约价格叠加，可归一化；后续扩展期限结构、跨期价差及 Contango/Backwardation 分析。

### 3. AI预测页面

- 短期预测：每2分钟更新；预测周期包含5分钟、30分钟、1天；展示方向、涨跌幅/价格及模型可提供的置信度；可选择 XGBoost、LSTM、Transformer、Random Forest 或集成模型；显示当前模型及下次更新时间。
- 长期预测：每天更新；预测周期建议为1个月、3个月；展示趋势、预测区间、置信度；可选择 ARIMA/SARIMA、Prophet、LSTM、Ensemble 等，并侧重基本面、库存、基差和中长期时序特征。
- 展示短期与长期当前模型，允许切换；解释模型选择依据、训练效果和影响因素。指标包括 RMSE、MAE、方向准确率等。解释因素可涵盖价格、成交量、库存、基差、技术指标和基本面。
- 预测结果须与诊断信息关联。短期重点为高频价格、成交量、技术指标；长期重点为库存、基差、产业基本面与长期趋势。
- 诊断摘要：残差走势/分布与异常、ACF/PACF/滚动统计等时域特征、Periodogram/频谱及主要周期、RMSE/MAE/Directional Accuracy/Ljung–Box 等性能指标。

### 4. 模型详情页面

从 AI预测页的明显“模型详情”入口进入独立页面，并可返回 AI预测。集中展示：模型名称/版本/训练时间/数据窗口/训练验证测试比例/验证方式；真实值与预测值；训练和验证 Loss；残差时间序列、分布/直方图、Q-Q 图；ACF/PACF、自相关和滚动均值/方差；Periodogram、频谱密度与周期峰值；特征重要性；RMSE、MAE、适用时的 MAPE、方向准确率及样本外结果。

### 5. 前端整体体验和更新

- 三个核心页面为平行导航，风格专业、偏金融研究终端，信息密度高但层次清楚、少装饰。
- 图表响应式，桌面优先并兼顾较窄窗口；同一模块允许多图并列。
- 实时数据、预测和训练结果显示时间戳/更新时间；示例或模拟数据必须清晰标记，不得伪装为真实市场数据。
- 更新建议：实时行情秒级或依数据源能力；短期预测每2分钟；长期预测每天；库存依发布频率并展示发布日期；资讯实时或定时轮询、按发布时间倒序；训练结果在每次重训后更新并保留版本/训练时间。

## 四、后端、数据和模型需求（来源：项目细节说明书）

### 1. 数据范围

- 行情字段：Open、High、Low、Close、Last、成交量、持仓量、可获得时的成交额；覆盖分时、日、月等粒度，主力、后两合约及连续序列。
- 期货结构：合约价差、期限结构、主力切换及移仓特征。
- 基本面 Profile：全国/总库存、地区库存、交易所仓单（与产业库存分开）；沥青产量、炼厂开工率、进出口、可获得的需求/道路施工消费代理；Brent、WTI、SC 等原油与必要能源指标；季节性。
- 新闻/事件：沥青、原油、炼厂、库存、开工、需求、道路施工、进出口、政策及突发事件。MVP先做聚合分类；事件量化影响属于后续增强。

### 2. 数据治理

- 关键数据保存来源、抓取/发布时间、更新时间、频率、单位和原始值；原始层与清洗层分离，模型不得覆盖原始数据。
- 明确区分仓单、社会库存、炼厂库存等定义；记录缺失值、异常值、单位转换、发布时间错位的处理规则。
- 严防未来信息泄漏；特征必须按其实际发布时间与预测时点对齐。
- 数据实体采用通用结构，建议 instrument → contract → frequency → observation/feature → model → forecast，避免 BU 写死。

### 3. 双引擎和候选模型

- 短期引擎（5m/30m/1D）：OHLCV、持仓、收益率、波动率、MA/EMA、MACD、RSI、BOLL、合约价差等；目标为短时方向、价格及区间。
- 长期引擎（1M/3M）：库存、产量、开工、进出口、需求、原油、季节性、期限结构等；目标为中长期趋势、价格区间和驱动因素。
- 多模型并行和统一评估，逐步形成 Ensemble。候选含 Naive/移动平均/EMA/技术规则基准，ARIMA/SARIMA/VAR，Random Forest/XGBoost/LightGBM，LSTM/GRU/Transformer，加权或动态 Ensemble。
- 技术和特征工程可含趋势、动量、波动、量价、期货结构、基本面、季节性和外部市场特征。

### 4. 验证、指标和真实性

- 不以随机打乱的普通 K-fold 作为时间序列主要依据。第一版采用时间有序训练/验证及完全独立最终测试区间；使用 Walk-forward、Expanding Window、Rolling Window、TimeSeriesSplit 等。
- 方向指标：Accuracy、Precision、Recall、F1、Balanced Accuracy、适用时 ROC-AUC。
- 价格指标：MAE、RMSE、适用时 MAPE/SMAPE；区间指标：Coverage、平均区间宽度、Pinball Loss；概率指标：Brier Score、Calibration Curve。
- 策略收益、最大回撤、Sharpe 属于后续策略研究，须与价格预测准确率分开展示。
- 展示历史表现；接近随机水平时提示“信号弱/不确定”；关键数据缺失/异常时允许暂停预测。复杂模型须证明相对基线有增量。

### 5. 页面优先级与建议技术架构

- P0：市场总览 Dashboard（主力价格、涨跌、量仓、主力+后两合约、期限结构、五周期预测摘要、新闻滚动）；行情分析；预测中心；基本面 Profile。
- P1：新闻与事件独立页面；Dashboard保留滚动摘要。
- 建议模块：Python 数据源 Connector/定时采集；PostgreSQL/TimescaleDB 候选；Pandas/Polars 清洗、对齐、换月和特征 Pipeline；scikit-learn、statsmodels、XGBoost/LightGBM、PyTorch 等模型；FastAPI 服务；React 前端与金融图表；轻量调度器和失败重试。
- 技术选型须在数据源调查后确认，以上为建议而非冻结选型。

### 6. 一个月计划和下一项工作

- Week 1：调查接入 BU 行情/基本面免费数据源、数据库、主力识别、主力+后两合约、原始数据和连续序列。
- Week 2：特征工程、指标、基线与候选模型、Walk-forward 训练验证和比较。
- Week 3：Dashboard、行情、预测、Profile、新闻页面及 API 接入。
- Week 4：回测、泄漏检查、区间与概率校准、异常处理、性能/UI 优化和部署。
- 需求冻结后的第一项正式开发工作：数据源调查与数据字典设计，核实免费/官方来源、稳定性、更新频率、发布时间、历史深度、授权与缺失情况，并标明数据分别能否支持5m/30m/日/月模型及未来可能需采购的数据/API。

## 五、两份文档的对应与待统一项

以下是整理备注，不是新的产品承诺：

1. 两份文档在三类核心分析能力上吻合：行情/可视化、基本面、AI预测；项目说明书进一步要求 P0 Dashboard、预测中心和 Profile，并将新闻独立页列为 P1。前端说明中的四个入口（基本面、数据可视化、AI预测、模型详情）可视作详细页面结构，Dashboard/新闻独立页是项目级补充。
2. 预测周期基本一致：前端短期列5分钟、30分钟、1天，长期列1个月、3个月；后端冻结为5m、30m、1D、1M、3M。
3. 更新频率需共同实施：短期结果按前端要求每2分钟刷新；长期每日刷新。刷新表示重新获取/计算或读取最新结果，具体计算与接口策略待后续技术设计。
4. 前端信息页提出现货价和基差；后端数据范围强调期货价差、期限结构，并将基差/价差作为预测输入，但没有明确现货报价数据源。需在数据源调查确认可用性、口径和是否列入 MVP 必交项。
5. 前端允许示例/模拟数据但必须标识；后端强调真实数据且不允许伪造真实数据。实现时如无真实源，可展示明确标记的演示样例或“数据暂缺”，不得包装为实盘/模型真实结果。
6. 后端成功标准要求概率/置信信息及预测区间可验证；前端将置信度描述为“如模型能够输出”。应优先按后端冻结口径实现，但仅在可校准/验证时展示数值，否则显示不可用或信号不确定，不臆造。
7. 前端文档提及若干候选模型与诊断图表，后端明确 MVP 应先对比基线、按数据充分性验证并防止过拟合；候选清单不等于首月必须全部上线。
8. 前端最初导航可理解为三大主模块；模型详情为 AI 的独立下钻页。后端另外要求市场 Dashboard 与 P1 新闻事件页，需在实际导航/路由方案中落实并确定入口。

## 六、后续实现时的执行约束

- 先调查数据源、定义数据字典和时间对齐规则，再冻结接口字段与模型可用特征。
- 任何数据、图表、预测、置信度、准确率、区间必须保留可追溯来源/版本/更新时间；无数据时显式呈现缺失状态。
- 需求范围以 BU MVP 和 P0 为主。新增品种、自动交易、复杂事件量化、付费/权限体系、策略执行等均属延后内容。
- 本记录是对两份 V1.0 文档的索引式整理，原始文档仍是具体措辞和表格的最终来源。
